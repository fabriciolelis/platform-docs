# ADR-008: Bootstrap, secrets, and environment layout for GitOps

- Status: Accepted
- Date: 2026-11-14

## Context

ADR-003 makes `platform-gitops` the only source of what runs in a cluster,
reconciled by Argo CD. Before the first workload manifest is written,
platform-gitops#2 asks four questions: how Argo CD itself gets into a cluster,
how secrets are kept out of Git in plaintext, how environments differ, and what
the environments are called.

The first environment is `local`, a k3d cluster on the maintainer's machine
(ADR-004). It is rebuilt often and holds no data that cannot be imported again,
so it is not a persistent environment (`GLOSSARY.md`). A `dev` environment on
the AWS K3s lab follows later and must not force a restructuring. The decisions
were worked out in the platform-gitops spec (`SPEC.md`) and approved for
Sprint 3 (`sprints/sprint-3-plan.md`).

## Decision

- **Bootstrap:** Argo CD is installed once per cluster with
  `kubectl apply --server-side -k bootstrap/argocd`, which applies the upstream
  install manifest pinned to an exact release, plus local patches. A root
  Application then deploys everything else ("app of apps"). Argo CD does not
  manage its own installation yet. Bootstrap is the only time anything is
  applied with `kubectl`.
- **Secrets:** SOPS with age. Encrypted files are committed; Argo CD decrypts
  them while rendering, through the KSOPS Kustomize plugin on its repo server.
  The age private key stays with the maintainer, is loaded into each new
  cluster at bootstrap, and never enters Git or CI. The public key is in
  `.sops.yaml`.
- **Environments:** Kustomize overlays. Each application has a `base/` and an
  `overlays/<environment>/` directory; `environments/<environment>/` holds
  only that environment's Argo CD Applications. An environment differs from
  another only in its overlay: image tag, resources, and secrets.
- **Environment names:** `local` (k3d) now and `dev` (the AWS lab) later.
  `prod` is removed from the intended structure until a cost review approves it
  (platform-infrastructure README).
- **Rollback:** a rollback reverts the promotion pull request in Git. It may be
  merged without review while the service is down, with the reason stated in
  the pull request. Argo CD's own rollback and `kubectl set image` are not
  used, because automated sync undoes any change that is not in Git. The schema
  is never reverted (ADR-007). The procedure is the rollback runbook
  (platform-docs#10).

## Alternatives considered

- **Argo CD managing itself from Git:** upgrades would also go through review,
  but a broken self-managed Argo CD cannot repair itself, and the first install
  still needs `kubectl`. Deferred until the setup is stable.
- **Installing Argo CD with its Helm chart:** equivalent result, but it adds
  Helm as a second templating tool next to Kustomize, which the repository
  already uses for everything else.
- **Sealed Secrets:** secrets are also committed encrypted, but the private key
  lives in the cluster's controller, so each `k3d cluster delete` loses it and
  every secret must be re-encrypted. SOPS with a maintainer-held age key
  survives rebuilds.
- **External Secrets Operator with a secret store (for example Vault or AWS
  Secrets Manager):** the better fit once a persistent environment exists, but
  it needs an external store to run and pay for, which `local` does not have.
- **Separate trees per environment:** each environment's manifests are copied
  in full, so a change must be repeated in every tree and drift goes unnoticed.
  Overlays keep the shared part in one place.
- **Helm charts for the application:** more flexible templating than this
  single service needs; plain manifests with Kustomize are easier to review.

## Consequences

- A rebuilt cluster reaches the same state from Git plus one bootstrap
  command and the age key; no secret is re-encrypted.
- The age private key is a single point of failure: losing it makes every
  committed secret unreadable. It needs a backup outside the repository.
- CI has no age key, so validating the manifests must skip or stub the KSOPS
  generator.
- Argo CD upgrades are manual, outside review, until it manages itself.
- Adding `dev` means a new overlay per application and a new
  `environments/dev/`, with no change to the bases.
- Implementation is tracked in platform-gitops#7; this ADR closes
  platform-gitops#2.
