# ADR-010: A static public site, published daily from CI to GitHub Pages

- Status: Accepted
- Date: 2026-11-28

## Context

On 2026-11-16, Sprint 5 was set to build something portfolio visitors can use
to read Formula Insights data. Two constraints shape it:

- The only environment, `local`, runs on k3d on the maintainer's laptop, so
  visitors cannot reach it, and it is off whenever the laptop is.
- ADR-004 caps AWS at USD 20 a month. The AWS lab design
  (`architecture/aws-time-boxed-validation-environment.md`) excludes an
  always-on environment, a public API, a load balancer, and an Ingress. Every
  session is destroyed the same day.

The design session of 2026-11-28 settled what visitors need. They read data
anonymously and change nothing, data up to one day old is enough, and the
site must be up when the laptop is off. Its pages are the five read endpoints
of the API. Platform evidence (SLOs, dashboards) is not for the visitor.

## Decision

- **A static public site, not a public API.** The public site is HTML
  generated from the API. Visitors never reach a cluster or a database.
- **Generated daily in GitHub Actions.** A scheduled workflow in
  `formula-insights-api` runs one publication a day, scheduled after the hour
  of the daily import, but independent of it:
  1. read from `platform-gitops` the image the `local` environment runs;
  2. start an ephemeral PostgreSQL and restore the historical data dump;
  3. run that image's importer for the current season, paced under ADR-006;
  4. start that image's API and render every page from its HTTP endpoints,
     with Python and Jinja (ADR-005), and no JavaScript;
  5. publish the result to GitHub Pages with `actions/deploy-pages`.

  The import in step 3 is part of the publication. It is not a daily import
  and does not count in the ingestion signal.
- **Historical data dump:** a GitHub Release asset in `formula-insights-api`,
  which does not expire. A manual workflow renews it by running a backfill in
  CI, paced under ADR-006. It is renewed only after a backfill or a re-import.
  The dump can be recreated from Jolpica, so it does not make the public site
  a persistent environment.
- **Hosting:** GitHub Pages at the default address
  (`fabriciolelis.github.io/formula-insights-api`), free for a public
  repository. It is not an AWS resource, so ADR-004's budget and Terraform
  rules do not apply. It is configured in the repository settings, and this
  ADR is its record.
- **Code location:** `web/` in `formula-insights-api`, because the site is
  part of the Formula Insights workload (ADR-001 amendment). A change to the
  API contract and the matching change to the site go in one pull request.
- **Failure:** a failed publication leaves the previous one online. GitHub's
  default notification for a failed workflow is the only signal in Sprint 5.
  Every page shows the date its data was taken.
- **Data licence:** Jolpica licenses its data under CC BY-NC-SA 4.0
  (`TERMS.md` in jolpica/jolpica-f1, last updated 2025-08-27). Every page's
  footer credits Jolpica F1 and the licence, with links. The site's generated
  content and the historical data dump are published under CC BY-NC-SA 4.0.
  The licence of the repository's code does not change.
- **Languages:** the site is generated once per language, English, Portuguese
  and Spanish, under path prefixes (`/en/`, `/pt/`, `/es/`), with the English
  home at the root and `hreflang` links between them. Only interface text is
  translated; data from Jolpica stays as Jolpica sends it. A static host
  cannot choose the language per visitor, and detecting it would need
  JavaScript.
- **Images:** generic icons in team colours, from a presentation table in the
  site. Real helmet designs, car photos and team logos are owned by their
  authors or by the teams and are not used.
- **Verification:** CI renders the site against a fixture API and checks the
  internal links of the output, so a contract change that breaks the site
  fails its pull request before any publication.

## Alternatives considered

- **Publish from the `local` cluster** after its daily import: it reuses the
  daily import, but the cluster would need a GitHub token with write access,
  turning its pull-only GitOps model around. It would also go stale whenever
  the laptop is off.
- **Always-on AWS environment** (one EC2 node with a public address): it is
  the only option with a live API, but it costs about three quarters of the
  monthly ceiling, contradicts the time-boxed lab design, and would expose the
  API, its `/metrics` included.
- **Tunnel to the laptop** (for example Cloudflare Tunnel): free and live, but
  up only while the laptop is.
- **Single-page app calling the API from the browser:** needs a public API,
  which the options above already rule out.
- **A JavaScript static-site generator** (Astro, Next.js export): more common
  for sites, but a second language and toolchain for five page types.
- **Cloudflare Pages:** equivalent hosting, but another account and token.
- **A full backfill in every publication:** no dump to keep, but about three
  hours of requests to Jolpica each day for data that does not change.
- **The dump as an Actions artifact:** artifacts expire after at most 90 days,
  and an expired dump would break publications silently.
- **Jolpica's own database dumps** (`docs/database_dumps.md` in
  jolpica/jolpica-f1): could replace the backfill that renews the dump. Their
  terms and format were not checked; worth reading when the dump is first
  renewed.

## Consequences

- The public site costs nothing and does not depend on the laptop.
- Every promotion to `local` reaches the public site at the next publication,
  which makes the site evidence of the delivery path.
- The public site is not an environment: it is not deployed by Argo CD, and
  promotion and rollback (glossary) do not apply to it directly. A rollback of
  `local` reaches the site at the next publication.
- Each language multiplies the pages and the generation time; about 1,100
  pages per language stay within GitHub Pages' limits.
- Interface text must exist in every language; a missing string fails the
  build.
- The publication is a second consumer of Jolpica, with a few requests a day.
  It must follow ADR-006 like the importer in the cluster.
- The data on the site is up to one day old, and older when publications
  fail. A freshness SLO is a candidate to define with alerting, in the first
  persistent environment.
- No Ingress is added, so the open item to block `/metrics` before exposing
  the API stays open and does not block Sprint 5.
- Implementation is tracked in the Sprint 5 plan (`sprints/sprint-5-plan.md`).
